## Context

当前项目使用Astro 4 + TailwindCSS + DaisyUI,基于Astrofy模板。首页(`index.astro`)包含姓名、简介、统计数据、开源项目、代表性项目、最新博客6个区块。项目页(`projects.astro`)包含4个HorizontalCard组件,点击全部跳转GitHub。项目内容素材已充分(CV中有详细的项目描述、已有5张技术图片)。

## Goals / Non-Goals

**Goals:**
- 首页英雄区重构:用结构化列表替代长段落,突出研究定位
- 创建3个项目详情页面,展示技术深度
- 调整导航逻辑:项目卡片 → 详情页 → GitHub(可选)
- 临时隐藏博客区域

**Non-Goals:**
- 配色主题变更(不在本次范围)
- 博客内容迁移(单独change)
- 新增"硬件平台"独立页面(GPT建议,当前内容体量不需要)
- 响应式布局重做(沿用现有DaisyUI响应式)

## Decisions

### 1. 项目详情页放在 `src/pages/projects/` 下

**决策**: 详情页URL路径为 `/projects/<project-name>`,与现有项目列表页同属一个目录。

**理由**:
- Astro的目录路由机制自然支持
- 保持URL语义一致性:`/projects`是列表,`/projects/mpc-thermal-control`是详情
- 侧边栏导航只需一个"项目"入口,无需新增导航项

**备选**:
- 方案B: 放在 `src/pages/` 根目录(如 `/mpc-thermal-control`)
  - 缺点: 侧边栏需要新增3个导航项,增加导航复杂度
  - 缺点: 不符合现有信息架构(项目列表在 `/projects`)

### 2. 项目详情页复用BaseLayout + 自定义内容组件

**决策**: 详情页面使用BaseLayout(保持侧边栏和导航),内部使用DaisyUI组件构建:
- `hero` 组件展示项目标题和一句话描述
- `card` 组件展示技术架构图
- `stat` 组件展示关键指标
- `timeline` 组件展示项目进展

**理由**:
- 最大化复用现有组件(不需要新建复杂组件)
- DaisyUI组件足够丰富,可以构建专业的项目展示页
- 与现有页面视觉一致

**备选**:
- 方案B: 新建 `ProjectDetailLayout` 组件
  - 缺点: 过度工程化,当前只有3个项目,不值得

### 3. 首页文案采用"研究故事线"结构

**决策**: 首页重构为:
```
┌─ 姓名 + 身份
├─ 一句话研究定位(50字以内)
├─ 研究兴趣列表(3条,每条独立一行)
├─ 社交链接区(保留)
├─ 统计数据区(优化开源项目指标)
├─ 开源/工程实践(JHTracker)
├─ 代表性项目(3个项目卡片 → 详情页)
└─ [隐藏] 最新博客
```

**文案方向**: 选择"能力导向 + 故事导向"的混合:
- 一句话定位: "构建面向高性能材料的智能增材制造系统——从硬件设计、热控算法到AI驱动的工艺优化"
- 研究兴趣列表化,避免技术术语堆砌

**备选**:
- 方案A(纯问题导向): "PEEK打印很难...我从零搭建了一套完整的解决方案..."
  - 太口语化,不适合学术主页
- 方案C(纯能力导向): "我是一名嵌入式工程师和3D打印研究者..."
  - 不够有力,缺乏"为什么"

### 4. 统计数据条优化

**决策**: 
- "开源项目"统计从"48 commits"改为更有说服力的指标(如主要仓库名称 + GitHub链接)
- 其他3个统计(EI论文、发明专利、自研设备)保持现有格式

### 5. 项目卡片链接变更

**决策**:
- 首页"代表性项目"区域3个卡片: `url="/projects"` → `url="/projects/<detail-page>"`
- 项目列表页(`projects.astro`): 增加"查看详情"按钮或整个卡片可点击跳转详情页
- JHTracker卡片保持不变(仍指向GitHub,因为它不是研究项目)

## Risks / Trade-offs

### [Risk] 项目详情页缺少高质量内容素材

**缓解**: 
- 现有CV中有详细的项目描述,可以直接使用
- 已有5张技术图片(`fig-*`系列)可充分使用
- 每个详情页控制在800-1000字,不需要写长文

### [Risk] 首页隐藏博客区域后显得空

**缓解**:
- 博客区域本就有3篇假内容,展示出来更尴尬
- 可以暂时移除该区块,等博客迁移后再加回
- 现有其他区块(开源实践 + 代表性项目)已经足够充实首页

### [Risk] 项目详情页SEO和可发现性

**缓解**:
- 从首页和列表页都有链接,导航路径清晰
- 侧边栏"项目"入口保持,用户可从侧边栏找到所有项目
- 当前阶段(个人主页,非公开推广)SEO不是主要关注点

### [Risk] 项目详情页维护成本

**缓解**:
- 每个项目详情页独立文件,维护简单
- 不需要新增数据模型或Content Collection
- 纯Astro组件,无需额外依赖
